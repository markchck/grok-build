# LLM 애플리케이션·에이전트 튜토리얼 — 커리큘럼

## 1. 문서의 목적과 범위

이 커리큘럼은 LLM 애플리케이션과 에이전트 프레임워크의 원리를 단계적으로 이해하고 직접 구현하기 위한 학습 설계안이다.
독자는 Python, FastAPI, 문서 처리, Milvus, OpenAI 호환 모델 서버를 다뤄본 개발자다.
설명은 한국어로 하고 전문 용어는 처음 등장할 때 의미를 풀어 쓴다.

집필 형식은 `../WRITING-GUIDE.md`를 따른다.

## 2. 학습 방향과 최종 프로젝트

학습 순서: LLM API 직접 호출 → RAG 직접 구현 → LangChain → LangGraph → 트레이싱·평가 → MCP·멀티에이전트 → Deep Agents → 통합 UI.

하나의 문서 분석 프로젝트에 기능을 누적한다. 새로운 개념은 작은 독립 예제로 익힌 후 프로젝트에 적용한다.
각 단계의 완성 코드를 제공해 앞 단계에서 막혀도 이어갈 수 있게 한다.

**최종 프로젝트**: 문서와 CSV를 검색·분석하고, 근거 링크가 포함된 답변과 다운로드 파일을 제공하는 문서 분석 에이전트.

최종 요청 예시:

> 업로드한 문서와 CSV에서 제품별 매출 변화를 분석하고, 원인을 문서에서 찾아 근거 링크와 함께 설명해줘.
> 작업 계획을 보여주고, 결과를 CSV로 다운로드할 수 있게 해줘.

기본 구현 방향은 Python + FastAPI, 단순한 웹 UI, Milvus, OpenAI 호환 모델 서버다.
구체적인 패키지 버전, 모델, 운영체제별 설치 명령, 관측 도구 선택은 각 장 집필 시 확인한다.
모든 OpenAI 호환 서버가 도구 호출·구조화 출력·스트리밍 등을 동일하게 지원한다고 가정하지 않는다.

### 용어 해석
- 사용자가 쓴 `middlestream`은 미들웨어와 스트리밍을 뜻하는 것으로 해석해 둘 다 포함했다. 확인된 정식 용어로 취급하지 않는다.
- "thinking 과정 표시"는 모델 내부 사고 원문을 노출하는 기능이 아니다. 실제 실행 이벤트, 도구 호출, 작업 계획, 상태와 짧은 판단 요약을 보여준다. 내부 추론을 재현했다고 주장하거나 가짜 사고 과정을 만들지 않는다.
- Agent-to-Agent는 내부 하위 에이전트 협업과 별도 A2A 프로토콜을 구분해서 다룬다.

## 4. 단계별 커리큘럼

### 1단계. LLM API 직접 호출하기
- **목표**: 프레임워크 없이 LLM 서버와 통신하는 기본 동작 이해.
- **학습 내용**: HTTP API와 OpenAI 호환 API의 관계. 모델 서버와 클라이언트 SDK의 차이. messages 및 system/user/assistant 역할. 모델 선택, 출력 길이, temperature. 일반 응답과 스트리밍 응답. 구조화된 JSON 출력. 타임아웃, API 오류, 재시도.
- **실습 결과**: 터미널에서 질문하고 답변을 받는 Python 프로그램.
- **완료 기준**: 서버 주소와 모델을 설정해 호출하고 일반 응답·스트리밍의 차이를 확인한다.

### 2단계. FastAPI와 대화 화면 연결하기
- **목표**: LLM 호출을 사용자가 이용할 수 있는 서비스로 만들기.
- **학습 내용**: FastAPI 대화 엔드포인트. 대화 기록과 세션 구분. SSE 기반 스트리밍. 답변 토큰과 진행 이벤트 구분. 요청 취소와 연결 종료 처리. 미들웨어를 통한 요청 ID·실행 시간 기록. HTTP 미들웨어와 에이전트 미들웨어의 차이.
- **실습 결과**: 답변이 실시간으로 나타나고 작업 상태를 확인할 수 있는 웹 화면.
- **완료 기준**: 답변과 상태 이벤트를 구분해 표시하고 요청별 로그를 확인한다.

### 3단계. Tool Calling과 에이전트 반복 실행
- **목표**: 모델이 도구 사용을 요청하고 애플리케이션이 실행하는 분담 이해.
- **학습 내용**: Tool의 정의와 입력 스키마. 도구 선택·인자 생성·실제 함수 실행의 역할 분담. 도구 결과를 모델에 전달하기. 모델 호출과 도구 실행을 반복하는 에이전트 루프. 입력 검증과 도구 오류 처리. 최대 실행 횟수·시간 제한. 도구 호출 내역과 진행 요약 표시.
- **실습 결과**: 계산 도구와 CSV 조회 도구를 사용하는 작은 에이전트.
- **완료 기준**: 모델 요청 → 함수 실행 → 결과 전달 → 최종 답변의 흐름을 로그로 확인한다.
- **장 구성 예시**: 매출 합계를 계산하는 완성 모습 소개 → 역할 분담 설명 → 계산 함수 작성 → 도구 등록 → 모델 호출 → 함수 실행 → 결과 전달 → 최종 답변 → 잘못된 인자·반복 호출 처리 → CSV 조회 도구 추가 과제.

### 4단계. 기본 RAG 직접 구현하기
- **목표**: 검색한 자료를 근거로 답변하는 흐름 직접 구현.
- **학습 내용**: 문서 읽기와 텍스트 추출. 청킹, 청크 크기와 중첩. 임베딩 생성. Milvus 저장과 벡터 검색. 문서명·페이지·원본 URL 메타데이터 관리. 검색 결과를 프롬프트에 전달하기. 근거 부족 시 답변 처리.
- **실습 결과**: 등록한 문서에 관해 질문하는 RAG 프로그램.
- **완료 기준**: 검색된 청크와 최종 답변의 관계를 확인하고 근거가 없는 질문을 처리한다.

### 5단계. 하이브리드 검색과 근거 링크
- **목표**: 검색 품질 개선과 근거 확인 기능 구현.
- **학습 내용**: Dense Vector 검색의 특성. Sparse 검색과 BM25의 관계. 키워드 검색과 의미 검색의 차이. 하이브리드 검색과 결과 결합. RRF·가중치 기반 결합의 개념. 메타데이터 필터링과 리랭킹. 답변 문장과 출처 ID 연결. 원문·문서 페이지·청크로 이동하는 링크. 허용된 출처만 사용하도록 검증해 가짜 출처 방지.
- **실습 결과**: 하이브리드 검색과 클릭 가능한 근거 링크를 갖춘 RAG.
- **완료 기준**: 동일 질문의 Sparse·Dense·Hybrid 결과를 비교하고 답변 링크가 실제 근거로 연결되는지 확인한다.

### 6단계. LangChain으로 재구성하기
- **목표**: 직접 만든 기능을 프레임워크로 바꾸며 이점과 한계 이해.
- **학습 내용**: 모델 인터페이스와 메시지. 프롬프트 템플릿과 구조화된 출력. 문서·임베딩·벡터 저장소·Retriever. Runnable 구성과 실행. Tool과 기본 에이전트. 모델·도구 호출 전후의 미들웨어. 직접 구현 코드와 LangChain 구현 비교.
- **실습 결과**: 기존 RAG와 도구 호출 기능을 LangChain으로 재구성한 서비스.
- **완료 기준**: 이전 구현과 동일한 입력으로 동작을 비교하고 프레임워크가 맡는 책임을 설명한다.

### 7단계. LangGraph와 오케스트레이션
- **목표**: 작업 상태와 실행 순서를 명시적으로 제어.
- **학습 내용**: State, Node, Edge. 조건 분기와 반복. 정해진 워크플로와 모델 판단의 조합. 병렬 실행과 결과 통합. 체크포인트와 실행 재개. 노드별 오류 처리와 재시도. FastAPI·작업 큐·LangGraph의 역할 구분.
- **실습 결과**: 질문 분류 → 검색 → 근거 확인 → 추가 검색 또는 답변 흐름.
- **완료 기준**: 조건별 분기와 저장된 상태를 확인하고 중단된 작업을 재개한다.

### 8단계. Human in the Loop와 무한루프 차단
- **목표**: 사람이 개입할 수 있고 실행이 통제되는 에이전트 구현.
- **학습 내용**: 실행 중단과 승인 후 재개. 승인·거절·수정 요청. 승인 대기 상태 저장. 중복 승인과 도구 중복 실행 방지. 최대 단계·시간·토큰 예산. 같은 도구·인자 반복 감지. 결과 변화가 없는 반복 감지. 제한 도달 시 중단 사유와 부분 결과 반환.
- **실습 결과**: 지정된 중요 작업 전에 승인을 받고 반복 한도 초과 시 종료하는 워크플로.
- **완료 기준**: 승인·거절·수정 흐름과 의도적으로 만든 반복 루프의 종료를 확인한다.

### 9단계. 트레이싱과 품질 평가
- **목표**: 오답·지연·실패 원인을 실행 기록으로 파악.
- **학습 내용**: Trace와 Span. Phoenix 또는 LangSmith 연결. 모델 입력·출력과 도구 호출 추적. 검색 결과·시간·토큰 사용량 기록. 검색 품질과 답변 품질을 따로 평가하기. 근거 링크의 정확성 평가. 실패 사례를 평가 데이터셋으로 만들기. 프롬프트·검색 방식 변경 전후 비교.
- **실습 결과**: 실행 경로 추적 및 고정된 질문 묶음으로 품질 비교.
- **완료 기준**: 실패 사례의 원인을 추적으로 찾아내고 개선 전후 평가 결과를 비교한다.
- 기본 로그는 2단계부터 남기며 전용 관측·평가 도구를 이 단계에서 도입한다. 두 제품을 모두 구축하는 것을 필수로 만들지 않는다.

### 10단계. MCP로 외부 도구 연결하기
- **목표**: 도구를 서버로 분리하고 공통 인터페이스로 연결.
- **학습 내용**: MCP Host·Client·Server. Tools·Resources·Prompts 차이. 로컬 함수 Tool과 MCP Tool 차이. 간단한 MCP 서버 구현. 문서 검색·CSV 조회 도구 연결. 연결 방식과 도구 탐색. 인증·권한·타임아웃·연결 오류 처리.
- **실습 결과**: 별도 MCP 서버의 검색·조회 도구를 사용하는 에이전트.
- **완료 기준**: 도구 탐색과 실제 호출을 확인하고 서버 연결 실패를 처리한다.

### 11단계. 멀티에이전트와 Agent-to-Agent
- **목표**: 여러 에이전트의 역할과 협업 방식 설계.
- **학습 내용**: 단일 에이전트와 멀티에이전트 비교. 조사·분석·검증 역할 분리. Supervisor 기반 위임과 Handoff. 공유 상태와 에이전트별 컨텍스트. 병렬 작업과 결과 통합. 내부 하위 에이전트 호출과 A2A 프로토콜 차이. MCP의 도구 연결과 A2A의 에이전트 협업 차이. 상호 위임 루프·실패·비용 제한.
- **실습 결과**: 조사·분석·검증 에이전트 협업 및 별도 에이전트와의 작업 교환.
- **완료 기준**: 내부 협업과 별도 A2A 연결을 구분해 시연하고 위임 제한을 확인한다.

### 12단계. Deep Agents와 Skills
- **목표**: 계획·파일·위임 기능을 조합해 복잡한 작업 처리.
- **학습 내용**: LangChain·LangGraph·Deep Agents의 역할 관계. 작업 계획과 하위 작업 생성. 중간 결과의 파일 저장. 긴 컨텍스트 관리. 하위 에이전트 위임. Skill의 지침·참조 자료·스크립트 구성. Skill과 Tool·시스템 프롬프트의 차이. 필요한 Skill 선택과 적용. 기존 워크플로 구현과 비교.
- **실습 결과**: 문서 조사·CSV 분석 Skill을 적용하는 Deep Agents 기반 분석 에이전트.
- **완료 기준**: Skill 적용, 계획 변경, 중간 결과 저장과 위임 내역을 확인한다.

### 13단계. 진행 화면과 CSV 다운로드 완성하기
- **목표**: 실행 과정을 이해하고 결과를 활용할 수 있는 사용자 경험 완성.
- **학습 내용**: Todo List의 대기·진행·완료·실패 상태. 계획 변경과 실제 실행 상태 동기화. 검색·분석·검증 단계 표시. 도구 호출 상태와 짧은 판단 요약 표시. 사용자 승인 UI. 출처 링크와 근거 미리보기. 분석 결과를 표로 구조화하기. CSV 생성·한글 인코딩·다운로드. 부분 실패·취소·재개 상태 표시.
- **실습 결과**: 작업 목록, 진행 상황, 승인 버튼, 근거 링크, CSV 다운로드를 갖춘 서비스.
- **완료 기준**: 최종 통합 요청을 실행하고 화면 상태·근거·다운로드 결과를 확인한다.

## 5. 최종 통합 과제 완료 기준
